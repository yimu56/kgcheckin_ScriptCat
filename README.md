# 酷狗签到 · ScriptCat 定时版

用 [ScriptCat（脚本猫）](https://scriptcat.org) 在浏览器里自动领取酷狗概念版 VIP，每天两张。

这是 [kgcheckin_QingLong](https://github.com/yimu56/kgcheckin_QingLong)（青龙面板版）的浏览器移植版：
不需要服务器、不需要 Docker、不需要青龙面板，装个浏览器插件就能跑。

## 文件说明

整个脚本就是 **一个自包含的 `kgcheckin.user.js`**，零外部依赖：

- 不 `@require` 任何第三方库
- 加密（MD5 / SHA-256 / HMAC / AES-128/256-CBC / RSA）全部是脚本内纯 JS 实现
- HTTP 走 `GM_xmlhttpRequest`，不需要起本地服务、不占端口
- 自带二维码编码器（byte 模式 / 纠错等级 M），扫码登录不依赖任何在线服务

### 它是怎么跑起来的

```
脚本猫触发 @crontab
  → 从脚本配置 + 本地存储读出账号
  → 逐个账号：校验 token → 听歌领 VIP → 看广告领 VIP → 查到期时间
       └─ 每周指定那天顺带续期 token，续期后写回存储
  → 汇总结果 → 系统通知 / 各渠道 webhook
```

所有请求在浏览器里直接发往酷狗自己的域名，没有任何中间服务器。

## 与青龙版的区别

| | 青龙面板版 | 本 ScriptCat 版 |
|---|---|---|
| 运行环境 | 青龙容器（Node） | 浏览器扩展后台 |
| 调度 | 青龙定时任务（cron） | `@crontab`（脚本猫定时脚本） |
| 账号存储 | 青龙环境变量 + 本地快照 | 脚本配置 + 本地存储快照 |
| 依赖 | axios / pako / qrcode 全要装 | **零依赖**，一个文件 |
| 登录 | 扫二维码 / 手机号 | 扫码 / 手机号 / 手动粘贴 token |
| 通知 | 青龙 sendNotify + 各渠道 | 浏览器系统通知 + 各渠道 webhook |
| 邮箱 SMTP 通知 | 支持 | 不支持（浏览器拿不到裸 TCP 连接） |

## 一、安装

### 1. 装 ScriptCat

Chrome / Edge：到 [scriptcat.org](https://scriptcat.org) 或浏览器的扩展商店搜索「ScriptCat」安装。

> 装完建议在插件设置里打开「**启用后台运行**」，否则关掉所有窗口后浏览器会退出，定时任务自然不会跑。

### 2. 装脚本

**方式 A：从文件安装（推荐，改起来方便）**

1. 把 `kgcheckin.user.js` 拖到浏览器窗口，或者打开 ScriptCat 面板 → 「添加脚本」→ 粘贴文件内容 → 保存

**方式 B：从链接安装（能自动更新）**

ScriptCat 面板 → 「添加脚本」→ 填 `https://raw.githubusercontent.com/yimu56/kgcheckin_ScriptCat/main/kgcheckin.user.js`

### 3. 检查定时规则

脚本头部这一行决定什么时候跑：

```js
// @crontab      * 1-6 once * *
```

含义是「每天 01:00–06:59 之间跑一次，当天只跑一次」。想换时间就改这行，
格式是标准的 5 段 cron：`分 时 日 月 周`（周 0 或 7 表示周日）。

几个常用写法：

| 写法 | 含义 |
|---|---|
| `* 1-6 once * *` | 每天 1 点到 6 点 59 分之间跑一次（默认） |
| `10 1 once * *` | 每天 01:10 跑一次 |
| `* 1,3,5 once * *` | 每天 1 点 / 3 点 / 5 点跑一次（先命中的那次执行） |
| `* once * * *` | 每小时最多跑一次 |

> 浏览器不是 7×24 开着的，所以默认给了 6 小时的时间窗，比固定一个时间点更不容易漏跑。
> 在脚本列表页把鼠标悬停在「运行状态」列上可以看到下次执行时间。

## 二、登录（三选一）

### 登录入口在哪？

脚本的登录菜单**不在**脚本列表页里，而在 **ScriptCat 弹出层**：

```
点浏览器工具栏的 ScriptCat 图标
  → 找到「酷狗概念版 VIP 自动签到」这个脚本（后台脚本，列表靠下）
  → 点开它的菜单，就能看到下面这几项
```

```
① 扫码登录（新增账号）
② 发送短信验证码（填写手机号）      ← 菜单带输入框时
② 发送短信验证码（用配置里的手机号）  ← 菜单不带输入框时
③ 手机号登录（填写验证码）          ← 菜单带输入框时
③ 手机号登录（用配置里的验证码）      ← 菜单不带输入框时
④ 立即签到（不等定时）
⑤ 查看当前账号
⑥ 清空本地账号
```

> 菜单名里带「填写」还是「用配置里的」，取决于所用 ScriptCat 版本是否支持带输入框的菜单。
> 两种都能用，不带输入框的那种就把值填到脚本配置里。

> 脚本启用后若检测到尚未配置账号，会弹出一条**系统通知**（安装后即可看到），
> 照通知里的指引走就行。如果实在找不到菜单，也可以直接用「方式三：手动粘贴 token」，不依赖菜单。

### 方式一：扫码登录（推荐）

1. 打开上面的菜单，点「① 扫码登录」
2. 运行日志里会画出一块**字符二维码**，同时（默认）会在新标签页打开一张大二维码
3. 用「酷狗音乐 APP → 扫一扫」扫描，并在手机上点确认
4. 看到「登录成功」即可，账号会自动存进配置

> 二维码约 2 分钟失效，脚本默认等 150 秒（配置里「登录 → 扫码等待时长」可改）。
> 不想把扫码链接发给第三方（默认用 api.qrserver.com 渲染大二维码）？
> 把配置里「**二维码用浏览器打开**」关掉，就只用运行日志里的字符二维码，完全本地。

### 方式二：手机号 + 短信验证码

**先在配置里填好手机号**（这是最稳的方式，任何版本都可用）：

脚本配置 → 「登录」组 → 填「**手机号**」（11 位纯数字）→ 保存。

然后：

1. 点菜单「**② 发送短信验证码**」→ 短信发出，日志里会写明「使用手机号 13\*\*\*\*\*\*\*01（来源：脚本配置）」
2. 收到短信后点菜单「**③ 手机号登录**」→ 在弹出的输入框里填验证码；如果菜单没有输入框，
   就把验证码填到配置里的「**短信验证码**」并保存，再点一次这个菜单

> 如果菜单弹出了输入框，手机号和验证码也可以直接在框里输，不用改配置 ——
> 填了就以输入框里的为准。手机号会记住，第二次登录不用重填。
>
> ⚠️ 验证码只有几分钟有效期，收到短信请**尽快**输入。日志里会显示这次用的是哪个手机号
> （打码后）以及来源，发不出去时先看这一行。

失败时日志会带上服务端给的原因，常见两种：

- 「验证码错误或已过期」→ 重新点一次「② 发送短信验证码」，然后立刻输入
- 「该手机号绑定了多个账号」→ 接口限制，只能用扫码登录

### 方式三：手动粘贴 token

脚本配置 → 「账号」组 → 「账号列表」里填 JSON 数组：

```json
[{"userid": "123456789", "token": "0123456789abcdef0123456789abcdef"}]
```

多个账号就往数组里多加几个对象。

> 怎么拿到 token？最省事的还是走方式一或方式二，登录成功后账号列表会自动填好。

## 三、配置项

ScriptCat 面板里点脚本的「配置」按钮即可编辑，分四组。

### 账号

| 配置 | 默认 | 说明 |
|---|---|---|
| 账号列表 | `[]` | JSON 数组，登录脚本会自动写入 |
| 登录后追加账号 | 开 | 关掉的话，新登录会覆盖整个列表 |

### 登录

| 配置 | 默认 | 说明 |
|---|---|---|
| 手机号 | 空 | 手机号+验证码登录用，**建议填上**（11 位纯数字） |
| 短信验证码 | 空 | 菜单不带输入框时才需要；菜单有输入框就直接在框里输 |
| 扫码等待时长 | 150 秒 | 「扫码登录」等手机确认的时间 |
| 二维码用浏览器打开 | 开 | 关掉则只用日志里的字符二维码 |

### 签到

| 配置 | 默认 | 说明 |
|---|---|---|
| 每天最多领取次数 | 8 | 看广告领 VIP 的最大次数 |
| 每次领取间隔 | 30 秒 | 两次领取之间的等待，别调太小 |
| 每周几续期 token | 0（周日） | 填 `-1` 关闭自动续期。酷狗 token 约两个月过期 |

### 通知

系统通知默认开。下面这些 webhook 配了就发，可以同时配多个：

| 渠道 | 配置项 |
|---|---|
| 企业微信机器人 | 企业微信机器人 key |
| 钉钉机器人 | 钉钉机器人 access_token（加签方式再加「钉钉加签密钥」） |
| 飞书机器人 | 飞书机器人 key |
| 云湖机器人 | 云湖机器人 key |
| Server酱 | Server酱 SendKey |
| PushPlus | PushPlus token（可加群组编码） |
| Telegram | 机器人 token + chat_id |
| Bark | Bark key 或完整推送地址（可加分组） |
| Discord | Webhook 地址 |

## 四、常见问题

**Q：菜单点不动 / 找不到菜单项？**
A：菜单**不在脚本列表页**，在 ScriptCat 弹出层里：点工具栏的 ScriptCat 图标 → 找到本脚本（后台脚本，列表靠下）→ 点开菜单。
脚本启用后会自动跑一次并注册菜单，如果弹出层里还没有，把脚本关掉再启用一次即可。
实在没有的话，直接用「手动粘贴 token」这条路，签到本身是定时任务，不依赖菜单。

**Q：运行日志里的字符二维码扫不出来？**
A：多半是日志的字体不是等宽字体，方块被拉变形了。三个办法：
① 开着配置里的「二维码用浏览器打开」，直接扫新标签页里的大二维码；
② 复制日志里的扫码链接，用任意本地二维码工具自己生成；
③ 改用手机号+验证码登录。

**Q：报「未配置账号」？**
A：先跑一次登录（扫码或手机号），或在配置的「账号列表」里手动填 `[{"userid":"xxx","token":"xxx"}]`。

**Q：报「token 过期或账号不存在」？**
A：token 失效了，重新扫码登录一次即可。

**Q：手机号登录一直失败？**
A：先看运行日志——那里会带服务端给的原因，还有一行「使用手机号 13\*\*\*\*\*\*\*01（来源：…）」，
能直接看出这次用的是哪个号、从哪儿取的。常见两种：

- 「验证码错误或已过期」：验证码只有几分钟有效期。重新点一次「② 发送短信验证码」，
  然后**立刻**点「③ 手机号登录」输进去。
- 「该手机号绑定了多个账号」：接口限制，只能改用扫码登录。

如果日志里是「没拿到手机号」，说明输入框、记忆、脚本配置三处都没有号码——
到脚本配置 →「登录」组 → 填「手机号」保存，再点一次菜单即可。

另外手机号要填 **11 位纯数字**，不要带 `+86`、空格或横线。

**Q：今天没跑？**
A：定时脚本只在浏览器开着的时候才会触发。默认时间窗是 01:00–06:59，
如果那个时段浏览器没开，那天就跳过了。可以点菜单「④ 立即签到」补一次，
或者把 `@crontab` 改成覆盖常用上网时段的窗口（例如 `* 1-23 once * *`）。

**Q：关掉浏览器还会跑吗？**
A：不会。但 ScriptCat 打开「启用后台运行」后，浏览器最小化到托盘仍能继续跑定时任务。

**Q：是否会泄漏账号？**
A：不会。token 只存在浏览器本地（ScriptCat 的脚本存储里），
请求只发往酷狗自己的域名；运行日志里所有昵称、userid、token 都做了脱敏。
唯一会外发的是「二维码用浏览器打开」时把扫码链接发给 api.qrserver.com，不需要可以关掉。

## 六、测试

脚本里有两块「手写轮子」——加密内核和二维码编码器，写错了不会报错，
只会在扫码或请求时静默失败。所以这两块都做了与成熟实现的交叉验证。

```bash
npm test              # 离线测试：加密内核 + 二维码 + 通知渠道 + GM 解析 + 登录流程
npm run test:live     # 真实接口联调：会去调酷狗的二维码接口
npm run test:sign     # 签到主流程（用无效 token 跑一遍）
```

全部 834 项断言，离线测试只需要 Node，不需要 npm 包也不需要 Python：

- **加密内核 493 项**：MD5 / SHA-256 / HMAC-SHA256 / AES-128/256-CBC / RSA
  （NO_PADDING 与 PKCS1 两种填充）全部与 Node 的 `node:crypto` 逐项对拍，
  包括随机数据往返、FIPS-197 标准向量、用自造密钥做私钥回收。
- **二维码 270 项**：矩阵与 npm `qrcode` 包在「指定版本 + 指定掩码」下逐位一致
  （版本 1~10、内容填满容量），掩码罚分与 Python `qrcode` 库的 ISO/IEC 18004 实现逐档一致，
  字符串渲染可无损还原回矩阵。
- **GM 解析 18 项**：模拟脚本猫「GM_* 只注入作用域、不挂 globalThis」的真实环境，
  断言所有 GM 函数都能被取到。取错了会导致日志和二维码标签页全部失效。
- **登录流程 39 项**：菜单在有/无 `CAT_registerMenuInput` 两种环境下的注册结果、
  手机号与验证码的必填校验、登录请求的字段结构（服务端已确认接受）、以及失败原因能否被识别成一句人话。
- **通知渠道 14 项**：渠道 key 不串号、标题正文正确、单渠道失败不影响其它。

> 只改 `kgcheckin.user.js` 的话，改完跑一遍 `npm test` 就行。
>
> 二维码的参考数据（`test/qr-reference.json`）是预生成的，所以跑测试不需要 npm 和 Python。
> 要重新生成的话看 `test/qr-reference.gen.js` 头部的三步说明。
